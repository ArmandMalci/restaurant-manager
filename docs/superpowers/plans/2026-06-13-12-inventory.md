# Plan 12 — Inventory Module

**Feature:** Give managers visibility into stock levels — track ingredients by unit, log deliveries/waste/corrections, and surface low-stock alerts — so they never run out of key items mid-service.

**Branch:** `feat/plan-12-inventory`

### Task 2 — InventoryService

**File:** `apps/api/src/inventory/inventory.service.ts`

Implement:
```typescript
findAll(): Promise<InventoryItem[]>          // ordered by name asc
findOne(id: string): Promise<InventoryItem>  // throws NotFoundException if not found
create(dto: CreateInventoryItemDto): Promise<InventoryItem>
update(id: string, dto: UpdateInventoryItemDto): Promise<InventoryItem>
remove(id: string): Promise<void>
adjust(id: string, dto: AdjustInventoryDto): Promise<InventoryItem>
  // delta can be negative (waste) or positive (delivery/correction)
  // new quantity = max(0, current + delta)
  // use Prisma.$executeRaw or update with increment for Decimal
```

**Decimal arithmetic:** Use `Prisma` `increment` / computed field pattern — do NOT use JS float arithmetic on Decimals. Example:
```typescript
await this.prisma.inventoryItem.update({
  where: { id },
  data: { quantity: { increment: dto.delta } },
})
// Then re-fetch to return updated record
```

**Low-stock flag:** `findAll` response should include a computed `lowStock: boolean` field = `quantity <= minStock`.

**Acceptance:** Service methods exist, NotFoundException thrown on missing id.

## Trade-offs

| Decision | Chosen | Alternative | Reason |
|----------|--------|-------------|--------|
| `InventoryUsage` recipe linkage | Deferred | Implement now | Requires recipe management UI; Plan 12 focuses on stock tracking |
| Decimal increment | Prisma `{ increment }` | JS arithmetic | Avoids float precision bugs on Decimal(10,3) |
| Low-stock flag | Computed in service | DB view | Keeps pattern consistent with other services |
| Unit type | Zod enum validation, Prisma String | Prisma enum | Prisma already created as String in init migration |
