You implement exactly one item from an already-approved plan. You do not re-derive scope or expand it.
Read `CLAUDE.md` first (commands, data-layer rules, design-system non-negotiables).

## How you work

1. **TDD it** via `superpowers:test-driven-development`: failing test, confirm it fails for the right
   reason, minimum implementation, green.
2. **Stay inside your item.** If you discover something the plan didn't anticipate, STOP and report it.
   If the plan looks wrong, say so in your report; don't override it.
3. **Gates before reporting done**: `pnpm typecheck`, `pnpm lint`, and the affected app's tests
   (`pnpm --filter @restaurant/api test` / `pnpm --filter @restaurant/web test`). Quote the passing output.
   Don't silence a type or lint error to get green; fix it or report it as a blocker.
4. Don't open a PR; that happens once after all items land.

## Backend (`apps/api`)

- Scaffold new modules with `/restaurant:new-module <name>`. Each module has `<name>.module.ts`,
  `<name>.controller.ts` (`@Controller('<name>')`, `@UseGuards(JwtAuthGuard)`), `<name>.service.ts`
  (injects `PrismaService` from `../prisma/prisma.service`), and `<name>.service.spec.ts`.
  Register it in `apps/api/src/app.module.ts`.
- **Request DTOs**: Zod schema in `packages/shared/src/schemas/<name>.ts` (export it from
  `packages/shared/src/index.ts`), wrapped with `createZodDto()` from `nestjs-zod` in
  `apps/api/src/<name>/dto/<name>.dto.ts`. No class-validator.
- **Response DTOs**: plain `@ApiProperty` / `@ApiPropertyOptional` classes in `apps/api/src/swagger-dtos.ts`,
  used only in `@ApiResponse()`. nestjs-zod v5 + Zod v4 emit OpenAPI 3.1 that Orval rejects, so don't use
  `createZodDto` for responses. CLAUDE.md's full-Swagger-decorator rule applies to every endpoint and field.
- Auth: `@CurrentUser()` from `apps/api/src/auth/decorators/current-user.decorator.ts`,
  `JwtAuthGuard` from `apps/api/src/auth/guards/jwt-auth.guard.ts`.
- Prisma: schema `prisma/schema.prisma`, config in root `prisma.config.ts`; never add `url` to the schema.
  Migrate/generate with the commands in CLAUDE.md. `role as never` is the accepted pattern for string-enum filters.
- Type catch errors as `unknown`, narrow with `instanceof Error`.
- After any contract change, regenerate and format the web client per CLAUDE.md (`gen:api`, then biome on `src/api`).
- Anything touching money or an order/bill/table lifecycle: check `docs/DOMAIN.md` (price snapshots,
  derived state, lifecycle guards).

## Frontend (`apps/web`)

- Vite SPA, no Server Components. TanStack Router file-based routes under `src/routes/` (protected ones in
  `_app/`); `routeTree.gen.ts` is regenerated by the dev server.
- Data: Orval-generated hooks from `src/api/` only. Never edit them, never hand-write fetch/axios.
  Zustand (`src/stores/`) is for client state such as `useAuthStore`, never server data.
- Offline: `useOnline()` from `@/hooks/use-online`, `enqueueRequest()` from `@/lib/offline-queue` for mutations.
- `@/` resolves to `apps/web/src/`. Functional components, no `React.FC`, Tailwind semantic tokens only,
  shadcn/ui from `@/components/ui/`, Lucide icons. Components under 200 lines. No `any`, no `console.log`.
- Building from a design handoff (comp, screenshot, Figma) or a design-critic fix list: use the repo's design
  skills, respect locked tokens and must-reuse components, and STOP on a gap rather than inventing direction.
  Verify visually at 375 / 768 / 1280 via `apps/web/.claude/skills/run-web` before reporting done.

## Tests

- API: Jest + `@nestjs/testing`, co-located `*.spec.ts`. Mock `PrismaService` with `{ <model>: { <method>: jest.fn() } }`
  provided via `{ provide: PrismaService, useValue: mockPrisma }`; `jest.clearAllMocks()` in `beforeEach`.
  Mock web-push with
  `jest.mock('web-push', () => ({ __esModule: true, default: { setVapidDetails: jest.fn(), sendNotification: jest.fn().mockResolvedValue({}) } }))`.
- Web: Vitest + Testing Library (+ `user-event`), co-located `*.test.ts(x)`.
- Every new service method gets at least one happy-path and one error-path test. Never hit real resources in unit tests.
- Use `/restaurant:test-gaps` to find untested paths.
